# 数据库迁移演练（隔离原型）

这套工具只准备可检查的副本，不修改源数据库、不停止服务、不切换版本，也不是生产部署工具。正式使用前必须先停止或隔离所有写入进程，并单独完成备份、上线窗口、恢复与回退方案；不要对正在运行的生产库操作。

## 已实现的范围

`deploy/migrations/001_initial_schema.json` 冻结了版本 1 的表和索引定义。`deploy/rehearse_migration.py` 可从一个绝对路径 SQLite 文件创建新的私有演练目录：

```sh
python deploy/rehearse_migration.py --source /absolute/path/to/offline.db --staging /absolute/path/to/new-review-folder
```

输出目录必须不存在，且父目录必须存在。工具通过 SQLite 备份 API 读取一个一致快照，保存 `original.db`，再从同一快照生成 `migrated.db`，检查完整性后，在后者的事务中创建缺失的版本 1 表和索引，并写入带清单校验摘要的版本记录。目录权限为 0700，数据库文件权限为 0600；这些权限不等于加密。两个文件可能包含全部私人数据，不应提交到仓库或上传。

未版本化的输入必须至少有 `users` 表，已有应用表及其索引必须与冻结定义一致。针对旧账单、分类和健身表，允许三个明确列出的非唯一复合索引缺失，并在事务中补建；其他必要索引缺失、额外的应用表索引或触发器、定义不一致、版本未知或清单摘要不匹配时直接失败。其他独立表保留。已达到版本 1 的兼容副本可以重复演练，不会重复写入版本记录。新建的来源控制表不创建账户连接，也不启用高驰同步。

此严格检查可能拒绝实际历史库；应先分析差异并为经过验证的具体结构设计新迁移，不能为了通过而手工改写版本标记或绕开检查。此版本只增加缺失的整表，不重建或修改已有表，也不自动处理任何未来版本。清单一经发布不得修改；后续版本需要独立迁移文件、校验和相应测试。

## 回退边界

`original.db` 是升级前同一快照的副本，可用于**离线比较与恢复演练**。升级副本出现错误时工具事务回滚并删除本次新建的演练目录，源文件不作为写入目标。演练不会自动替换数据库或恢复服务。

实际回退需要首先停止所有写入，判断升级后新增数据的损失窗口，并制定数据库、媒体、来源凭据与密钥的一致恢复计划。直接恢复原始快照可能使旧会话、JWT 或来源状态重新生效；应另行核实会话撤销、签名密钥切换以及来源暂停，不能把 `original.db` 直接上线。现有 `deploy/prepare_restore.py` 有相关隔离恢复准备能力，但尚未与本迁移演练组成经验证的生产切换流程。

## 验证范围与不足

隔离测试使用虚构账户和临时 SQLite，覆盖 WAL 快照、账户和额外表的数据保留、缺表创建、不自动启用来源、版本校验、重复演练、中途注入失败的事务回滚、原文件保留和权限。已将升级副本交给现有结构检查工具核验。测试不能证明全部历史库兼容，也未演练磁盘写满、系统掉电、服务切换、备份加密或多数据库协作；没有读取真实数据库或部署。
