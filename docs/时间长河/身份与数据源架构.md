# 身份与数据源：逐步演进的边界

更新日期：2026-10-28。此文记录已实现的基础与尚未解决的决策，不表示微信免登录已上线。

## 需要守住的行为

- 用户打开小程序无需输入账号即可浏览示例；真实私人数据只允许经服务端确认的本人读取。
- 外部身份、抱布记账户、高驰等数据源和时间长河分别承担不同职责。小程序不直接决定某个微信身份属于哪个抱布记账户；高驰账号与微信身份不应直接耦合。
- 未来首次绑定需同时证明用户控制已有抱布记账户和外部身份。只凭客户端发送的 openid、手机号或 user_id 不足以建立绑定；对未绑定身份不能自动关联已有用户。
- 不同账户数据严格隔离；授权、连接、撤销、同步、删除及恢复都需要可验证的行为，不假设某一次授权永久有效。

## 模块边界

1. **提供方适配器**：在服务端通过可信渠道验证一次性凭据并获取提供方身份。具体微信流程仍需按官方文档、真实平台配置和有效期验证；第三方异常要收敛为无敏感信息的错误。
2. **身份绑定模块**：只接收内部已验证身份，绑定已认证的本地账户；唯一约束阻止一个身份绑定多个账户或同一账户重复绑定同一提供方。允许幂等重试，不自动创建用户、不提供 HTTP 接口。
3. **会话模块**：后续在解析成功后发放短期会话，并支持失效、退出和撤销。现有用户名密码 JWT 长达 720 小时；目前解绑不会使已有 JWT 失效，不得宣传为完整的撤销。
4. **数据源模块**：高驰授权和调度使用已确认的内部 user_id，保存专有凭据，独立于身份提供方。后续的照片和其他来源同理。
5. **回忆模块**：只接受已认证内部账户，按 user_id 读写；不用识别微信或高驰具体协议。

## 本次实现及限制

- 新增 `external_identities` 表及 `backend/identity/bindings.py`，提供绑定、解析和解绑的内部原语。提供方与外部 subject 通过 HMAC 摘要存储，密钥需以高熵随机值提供，不能提交或输出。密钥更换、备份与丢失恢复尚无实现，必须在上线前设计；丢失密钥会导致无法解析现有绑定。
- 唯一性由数据库约束保证；服务端验证和本地账户认证由未来调用者负责。`VerifiedIdentity` 只是内部类型，不是安全认证机制，绝不允许客户端直接提供它。
- 函数目前提交调用者提供的数据库会话，应使用独立事务；密钥轮换、迁移及现有会话撤销机制未完成。数据库首次创建、迁移、备份和回退必须先在隔离环境演练，切勿直接将原型部署到真实数据库。
- 测试使用虚构身份和隔离 SQLite，不访问微信或服务器。具体提供方协议、超时、错误处理、首次绑定流程和小程序端尚未实现。

## 下一个可验证增量

核实微信官方会话交换接口，构建可替换的提供方适配器并模拟成功、失败、超时和重复凭据；然后设计首次绑定与可撤销会话，在隔离环境联调。之后再把已绑定的内部账户连接高驰同步，最后由时间长河读取真实回忆。每次只将验证完成的功能部署到对应环境，记录变化与回滚方案。

## 2026-10-28：提供方适配器增量

新增 `backend/identity/wechat.py`，通过独立服务端接口交换一次性凭据，并在返回的内部身份中隔离不同 AppID；不记录或返回会话密钥。通信不自动重试、不跟随重定向并限制响应读取。以上只有模拟测试，微信官方详细协议、本机及生产网络配置尚待实测；尚无 HTTP 路由，不能自动登录。生产日志、反向代理和诊断工具也不能记录带敏感查询参数的上游请求 URL。

## 2026-10-28：可撤销会话原语

新增与微信协议解耦的短期不透明会话原语，支持单个和账户级撤销，只保存令牌摘要。原语尚无 HTTP 接入，仍需设计与解绑的原子性、清理、生命周期管理、旧 JWT 迁移与撤销；当前系统仍使用原有长期 JWT，不能宣称整个系统已支持即时撤销。

## 2026-10-28：解绑事务增量

内部协调服务将外部身份解绑与新式会话撤销一起提交，测试覆盖失败回滚和账户隔离；不覆盖并发签发与解绑竞态。底层单独解绑原语不能用于完整撤销，旧 JWT 不受影响；正式接入前必须解决上述问题，并完成会话迁移策略和数据库演练。

## 2026-10-28：SQLite 并发签发边界

身份签发和解绑协调服务使用专用 SQLite 会话与 `BEGIN IMMEDIATE` 先取得写入锁，确保两种操作按顺序执行。调用层不得绕过此服务使用低层 `issue` 或 `unbind`；服务只支持 SQLite，未来更换数据库需设计相应隔离机制。该保障不覆盖旧 JWT 或其他发放途径，也不能中止已经获得授权、正在执行的请求。当前仅做了隔离测试，尚未上线。

## 2026-10-28：认证入口兼容新旧会话

现有受保护 HTTP 接口可在隔离测试中验证数据库中有效的新式不透明会话，同时保留旧 JWT 路径。撤销新会话后再次请求被拒绝，旧 JWT 不受影响。尚无签发或绑定路由、生产迁移和实际联调；旧凭据撤销策略及并发中的在途请求仍需设计。

## 2026-10-28：实验性 HTTP 组合

新增默认禁用的身份流程路由，在模拟提供方与隔离数据库中验证已有账户绑定、身份会话签发、读取和撤销。短期凭据响应禁止缓存。旧 JWT 仍然有效，绑定与在途请求的并发、旧凭据撤销、首次绑定额外保护、限流、迁移和真实服务协议均未完成；不要启用生产开关。

## 2026-10-28：账户凭据代次增量

实验性解绑事务现在同时递增账户 JWT 代次并撤销新式会话；旧 JWT 代次默认为 0，仅在当前代次也是 0 时可用，后续密码登录签发当前代次。认证要求 JWT 含过期字段并确认账户存在。此变更仍未部署；数据库备份回滚或恢复旧版代码可能令旧凭据复活，须在上线前制定密钥轮换、迁移和恢复方案。此机制不停止已通过认证的在途请求。

## 2026-10-28：旧备份恢复隔离演练

在隔离数据库中验证：旧备份配旧 JWT 签名密钥会使旧 JWT 和短期会话恢复可用；恢复时更换 JWT 签名密钥，并在恢复的数据库中撤销所有短期会话，可使两类旧凭据失效。该测试不等于生产恢复方案：部署前仍需设计停机、备份验证、安全轮换密钥、原子切换、失败回退和旧版本服务不可继续接受旧凭据；身份 HMAC 密钥不能随意更换，否则无法解析原有绑定。
