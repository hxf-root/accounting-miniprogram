# 身份与数据源：逐步演进的边界

更新日期：2026-10-28。此文记录已实现的基础与尚未解决的决策，不表示微信免登录已上线。

## 需要守住的行为

- 用户打开小程序无需输入账号即可浏览示例；真实私人数据只允许经服务端确认的本人读取。
- 外部身份、抱布记账户、高驰等数据源和时间长河分别承担不同职责。小程序不直接决定某个微信身份属于哪个抱布记账户；高驰账号与微信身份不应直接耦合。
- 未来首次绑定需同时证明用户控制已有抱布记账户和外部身份。只凭客户端发送的 openid、手机号或 user_id 不足以建立绑定；对未绑定身份不能自动关联已有用户。
- 不同账户数据严格隔离；授权、连接、撤销、同步、删除及恢复都需要可验证的行为，不假设某一次授权永久有效。

## 模块边界

1. **提供方适配器**：在服务端通过可信渠道验证一次性凭据并获取提供方身份。具体微信流程仍需按官方文档、真实平台配置和有效期验证；第三方异常要收敛为无敏感信息的错误。
2. **身份绑定模块**：只接收内部已验证身份，绑定已认证的本地账户；唯一约束阻止一个身份绑定多个账户或同一账户重复绑定同一提供方。允许幂等重试，不自动创建用户、不提供 HTTP 接口。
3. **会话模块**：后续在解析成功后发放短期会话，并支持失效、退出和撤销。现有用户名密码 JWT 长达 720 小时；目前解绑不会使已有 JWT 失效，不得宣传为完整的撤销。
4. **数据源模块**：高驰授权和调度使用已确认的内部 user_id，保存专有凭据，独立于身份提供方。后续的照片和其他来源同理。
5. **回忆模块**：只接受已认证内部账户，按 user_id 读写；不用识别微信或高驰具体协议。

## 本次实现及限制

- 新增 `external_identities` 表及 `backend/identity/bindings.py`，提供绑定、解析和解绑的内部原语。提供方与外部 subject 通过 HMAC 摘要存储，密钥需以高熵随机值提供，不能提交或输出。密钥更换、备份与丢失恢复尚无实现，必须在上线前设计；丢失密钥会导致无法解析现有绑定。
- 唯一性由数据库约束保证；服务端验证和本地账户认证由未来调用者负责。`VerifiedIdentity` 只是内部类型，不是安全认证机制，绝不允许客户端直接提供它。
- 函数目前提交调用者提供的数据库会话，应使用独立事务；密钥轮换、迁移及现有会话撤销机制未完成。数据库首次创建、迁移、备份和回退必须先在隔离环境演练，切勿直接将原型部署到真实数据库。
- 测试使用虚构身份和隔离 SQLite，不访问微信或服务器。具体提供方协议、超时、错误处理、首次绑定流程和小程序端尚未实现。

## 下一个可验证增量

核实微信官方会话交换接口，构建可替换的提供方适配器并模拟成功、失败、超时和重复凭据；然后设计首次绑定与可撤销会话，在隔离环境联调。之后再把已绑定的内部账户连接高驰同步，最后由时间长河读取真实回忆。每次只将验证完成的功能部署到对应环境，记录变化与回滚方案。
