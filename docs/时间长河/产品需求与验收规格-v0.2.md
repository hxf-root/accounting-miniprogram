# 抱布记产品需求与验收规格 v0.2

日期：2026-10-28。状态：**审查提出的开发建议基线，新增默认值待产品试用校准**。本文件不表示功能已实现或已获上线授权。

## 1. 产品定义与范围

抱布记是私人生活素材的自动收集与回看工具：尽量利用已有记录，在有空时自由浏览，偶遇遗忘的普通瞬间。首要价值是减少逐条记录负担，同时让用户知道素材来自哪里、采集是否正常，并能控制其保留与展示。

### 已确认的约束

- 主要自用、默认仅本人可见，未来可能加入伴侣共同空间。
- 数据保存在既有私人服务器；公开 GitHub 只保存代码、方案和脱敏验证记录。
- 安卓默认只同步用户选定相册。新增相册不会自动入选，读取授权不等于上传同意。
- 优先高驰运动和安卓照片；地点、阅读、音乐、支付、AI 对话按来源能力逐项评估。
- 旧账单、健身数据保留；小程序旧入口已移除，不自动恢复。
- 模块化开发、阶段性详细验证、记录并归档。

### 两个交付层次

| 层次 | 目的 | 必须包含 | 不以其为完成条件 |
|---|---|---|---|
| A：受控真实数据试用 | 验证采集到回看的完整链路 | 已有账户进入、一个高驰连接、摘要同步及状态、真实回忆、文字补记、日期浏览、偶遇、隐藏/删除、可恢复备份 | 安卓、地图、全部历史、伴侣共享 |
| B：生活素材首版 | 验证日常使用价值 | A + 安卓选定相册、可靠上传、照片详情、媒体备份恢复、权限撤销与设备验证 | 视频/实况照片完整支持、持续定位、其他平台全自动接入 |

A 是中间试用，不应宣传为整个产品完成；B 中照片比复杂动画更优先。

## 2. 需求与验收矩阵

| 编号 | 需求 | 可观察验收 | 阶段 |
|---|---|---|---|
| REQ-01 | 私人身份与示例浏览 | 未登录不请求私人接口；示例标识持续可见；身份失效立即清除私人页面内容 | A |
| REQ-02 | 连接已有账户与恢复会话 | 首次确认本地账户；绑定冲突可解释；会话恢复成功可读自身数据；恢复失败可回到登录 | A |
| REQ-03 | 来源状态可见 | 展示连接状态、上次成功、已覆盖时间范围、待处理/失败与操作入口，未知范围明确标未知 | A |
| REQ-04 | 高驰摘要增量采集 | 同一来源 ID 重跑不重复；失败不推进覆盖；活动更新不覆盖用户笔记；暂停后不再提交新结果 | A |
| REQ-05 | 历史回填 | 用户明确范围后分段处理；部分完成可恢复；超过上游能力时明确显示缺口 | A |
| REQ-06 | 时间浏览 | 按日期跳转，顺序稳定；分页新增/删除不导致重复；可返回上一浏览锚点 | A |
| REQ-07 | 偶遇历史 | 候选覆盖完整可见历史，排除隐藏/删除/不参与项；多条时避免立即重复；无候选时明确提示 | A |
| REQ-08 | 详情与文字补记 | 详情显示来源、时间、内容；支持可选手写备注与独立文字记录；重复提交不重复创建 | A |
| REQ-09 | 隐藏、排除偶遇、删除 | 三种语义分别可解释；隐藏可恢复；删除的外部记录不因常规同步或默认导入复活 | A |
| REQ-10 | 断网与授权错误 | 网络失败与身份失败不同处理；同账户网络失败保留当前已载内容；重试次数受控 | A |
| REQ-11 | 选定相册采集 | 未选相册零上传；撤销权限后停止新读取；取消选择后取消未提交任务；已上传内容保留或单独删除 | B |
| REQ-12 | 照片上传与查看 | 上传重试幂等；损坏/超限内容不成为可见回忆；仅本人能访问原图和派生图 | B |
| REQ-13 | 数据导出与恢复 | 导出版本可验证，含全部已支持内容；默认导入预览且保留删除意图；系统备份恢复经过隔离验证 | A/B |
| REQ-14 | 可控停止 | 暂停来源、解绑登录身份、退出设备、删除内容分别操作，不互相冒充 | A/B |
| REQ-15 | 可解释的时间和来源 | 未知拍摄时间、时区或缺少路线明确展示；系统不虚构地点、心情或经历 | A/B |

## 3. 页面与主要流程

### 首页/时间长河

建议让时间长河成为主要首页内容，减少当前“问候页再点击进入”的一层跳转；这一信息架构调整先做可用性验证，不在本轮重做视觉。

主界面包含一个当前瞬间、遇见另一个瞬间、按日期进入历史、来源状态轻提示。普通时间列表始终可达，光点只是可选探索方式。字体放大、触控目标、图片加载占位与低端机流畅性纳入验收。

| 页面状态 | 展示 | 操作 |
|---|---|---|
| 未连接 | 清楚标记的示例与私人空间入口 | 连接已有账户 |
| 已登录但无来源 | 空状态与来源连接说明 | 连接高驰、稍后配置安卓 |
| 来源已连接但无回忆 | 已覆盖范围、首次同步进度 | 手动同步/稍后再看 |
| 加载中 | 已有内容或骨架；不把真实内容标成示例 | 等待、取消 |
| 部分同步失败 | 当前真实回忆与明确错误状态 | 重试、重新授权 |
| 当前设备断网 | 同账户当前页标记未更新 | 重试 |
| 会话失效 | 立即移除私人内容，恢复身份或返回入口 | 重新连接 |
| 正常 | 真实内容、来源、日期 | 前后浏览、偶遇、详情 |

A 阶段不新增持久化私人内容缓存；仅保持当前会话内数据。退出、账户切换或鉴权失败清除内存。B 阶段若缓存缩略图，需有账户作用域、清理与撤销策略，不能把微信临时文件当作安全存储保证。

### 来源管理

高驰连接与微信登录分开呈现。来源卡片至少包含：名称、状态、上次尝试、上次成功、可证实的历史覆盖、错误行动、暂停/恢复、重新授权、断开。

推荐来源状态：`disconnected → authorizing → ready → syncing`，以及 `paused / needs_reauth / degraded / recovery_required`。状态属于服务器事实；手机本地“自动识别开启”是独立偏好。

同步成功必须意味着指定区间处理完成且已提交，不能以请求发出、拿到 token 或收到部分响应标记成功。进度无法准确计算时展示“已完成若干时间段”，不伪造百分比。

### 详情与管理

运动摘要显示类型、发生时间和供应商可提供的摘要；单位标准化，字段缺失留空。用户补充的备注独立于供应商原文，后续同步不会覆盖。

照片详情显示可用拍摄时间、照片与自写备注；地点默认关闭。没有可靠拍摄时间时允许用户修正，保留时间来源。原文件名只在必要时展示，不作为唯一身份。

隐藏管理从“我的”进入，隐藏项不参加普通列表和偶遇。删除使用准确后果说明，表示从抱布记移除，不删除高驰或手机原始数据。

## 4. 数据生命周期契约

| 操作 | 已收录内容 | 后续采集 | 撤销/恢复 |
|---|---|---|---|
| 隐藏 | 保留，普通浏览不可见 | 来源更新可继续，但不改变隐藏 | 可取消隐藏 |
| 不参与偶遇 | 正常列表可见 | 不变 | 可重新开启 |
| 删除单条 | 用户界面立即不可见，媒体进入清理流程 | 对同一连接/来源键保存删除抑制 | 如要支持回收站须另定期限；默认不偷偷恢复 |
| 暂停来源 | 保留 | 不启动新任务，在途提交受代次校验阻断 | 恢复后按覆盖区间补读 |
| 断开来源 | 默认保留，另提供删除选项 | 删除/撤销可撤销凭据，停止任务 | 新授权核实是否同一来源账户 |
| 取消某相册选择 | 已上传保留 | 取消该范围未提交任务，阻止新的上传提交 | 重新选择按同一身份幂等继续 |
| 退出当前设备 | 服务端数据保留；清客户端内容 | 来源后台同步按既有授权继续 | 此设备会话撤销 |
| 解绑微信 | 回忆与来源仍归本地账户 | 不等同于断开高驰/安卓 | 撤销相应登录能力并按策略撤销账户会话 |
| 清空内容 | 清除目标范围数据；保留必要抑制 | 默认暂停有关来源 | 再次导入必须明确说明后果 |
| 默认导入历史导出 | 预览后合并，不撤回现有删除意图 | 检查点按覆盖证明重建 | 冲突明确选择，不隐式重置 |
| 灾难恢复 | 按已验证备份恢复，并应用可用的最新删除记录 | 校验后逐个恢复任务 | 轮换 JWT、撤销会话；删除记录损失须说明 |

备份保留窗口内可能仍含历史已删除字节；产品应如实说明保留期限及清理过程。不能仅删除线上行就声称所有备份已同步擦除。期限在媒体阶段确定并实际执行。

## 5. 采集规格

### 高驰

- 建议默认定时每小时一次，作为试用初值；实际频率根据上游限制和用户接受度调整，不承诺实时。
- 首次授权先同步近期摘要，再显式发起选定历史范围的回填；界面显示范围，不默认“全部历史已完成”。
- 连接只能对应已验证的本地账户与来源账户，重授权时核对来源身份；无法取得稳定外部账户标识时先保持人工验证，不静默混入另一个账号。
- 读取、解析、校验、事务提交分别可失败；未知格式隔离并保留固定错误码，不输出原始私人响应。
- 默认只采集运动摘要，不因 MCP 另有能力便收集健康、周期或其他无关数据。
- 路线/FIT 是可选增强：单独同意地点处理，配额与失败不影响已完成摘要。短期下载链接不作为长期存储引用，也不写入公开文档。

### 安卓照片

- 相册选择结果清楚展示；新增相册默认未选。每次扫描和上传前检查范围、授权及同步代次。
- 建议默认仅非计费网络自动上传；手动允许本次移动网络。充电要求可配置，试用期根据设备行为调整。
- 首版先支持静态 JPEG/PNG；HEIC、动图、实况照片、视频明确显示暂不支持或单独处理，不能静默声称已完整备份。
- 一次性选择照片与持续相册同步分别命名；权限变更后重新核对可读范围。
- 同步队列持久保存，区分待传、上传中、已提交、待重试、永久拒绝；只有服务端提交成功才能记录已上传版本。
- 断网/杀进程不生成云端删除；手机删除原图也不默认级联删除抱布记回忆。
- 跨设备与重装不以本机媒体 ID 单独去重；账户内内容散列可作为辅助，但不同来源记录是否合并需要规则，禁止跨用户散列探测。

## 6. 偶遇算法首版

目标是增加跨时间探索机会，避免最近高频运动挤占旧照片。建议先均匀选取有候选的月份，再在该月份按来源或类型分层选记录；这不是“全记录等概率”，需在开发说明中写清。

候选条件：本人、可见、未删除、允许偶遇、媒体已就绪。接口内部校验排除项，客户端不能用其他账户 ID 推断记录是否存在。会话内维护最近见过集合，数量设上限；候选不足时逐步放宽短期去重，但永不放宽隐藏/删除限制。

验收使用至少三年、多个来源、超过 50 条的固定虚构集合，确保未加载的老记录有机会返回；用可控随机种子或穷举边界验证，不依赖偶发概率来让测试过关。

## 7. 非功能需求与试用指标

以下是建议验收目标，不是现有实测成绩：

| 项目 | 建议目标/边界 | 验证方式 |
|---|---|---|
| 数据隔离 | 跨账户读取、修改、媒体下载均拒绝 | 两账户 HTTP 与文件访问测试 |
| 幂等 | 相同任务重试不重复创建 | 提交前后故障注入、并发重试 |
| 响应 | 基准单机、1 万条合成文本、5 并发下列表 API P95 ≤ 500ms | 固定环境与数据报告；不包含上游调用 |
| 手机体验 | 指定目标机和已记录网络条件下可交互首屏目标 ≤ 2s | 真机记录；未达标定位网络、渲染或媒体 |
| 列表内存 | 默认页 50，前端有界窗口建议最多 200 条 | 长时间浏览后内存与 setData 体积检查 |
| 恢复 | A 阶段建议 RPO ≤ 24h、RTO ≤ 4h | 从隔离副本实际恢复计时；B 含媒体后重估 |
| 同步时效 | 授权有效、上游可用条件下，高驰目标 2h 内可见 | 连续试用记录；失败必须显性 |
| 安卓时效 | 不承诺固定后台期限；立即同步提供可解释结果 | 重启、断网、系统省电、权限撤销实测 |
| 隐私 | 日志、CI、公开仓库中无真实记录或凭据 | 定向扫描和输出检查 |

产品试用建议至少连续七天：用户能分辨失败与无数据；能遇到近期列表外的旧记录；删除后不回流；日常新增能在无需逐条手动操作的条件下到达。只保存必要的本地/私有运行统计，不为评测上传内容到第三方分析平台。

## 8. 后续决策清单

不阻塞文档与基础修复、但实现相关模块前需决定：目标安卓机型和系统；首批历史回填范围；是否保存原图及其元数据；备份保留期和存储预算；密码恢复方式；对“痛苦但想保留”的内容是否采用排除偶遇开关；FIT 路线是否值得首轮做。

本轮建议默认个人使用、关闭公开注册、选定相册、位置关闭、静态照片优先。共享空间、公开分享、AI 自动叙事和持续位置采集不列入首版。
