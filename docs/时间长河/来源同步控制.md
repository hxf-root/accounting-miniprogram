# 来源同步控制：高驰隔离原型

此文描述来源同步控制的实现及限制。用户授权后，已为指定账户在服务器配置独立高驰授权、执行首次同步并启用每日定时任务；这属于单账户受控接入，不代表通用的多账户授权和解绑流程已经完成。

## 用户能看到什么

设置页在已登录时尝试读取高驰同步状态。`unconfigured` 表示没有本地控制记录，`active` 表示允许已配置的任务尝试同步，`paused` 表示暂停。页面也会展示最后一次成功处理的日期；这不是完整历史覆盖范围。旧服务器、网络异常或接口不可用时显示状态暂不可用，不猜测已经连接。

对已有控制记录，用户可暂停或恢复。服务端只按认证账户查找记录，不接受客户端 user ID；暂停/恢复在 SQLite 写事务内重新验证会话。恢复只重新允许任务尝试，不检查高驰凭据是否有效。

目前没有通用的高驰连接、解绑或来源控制记录创建界面/API。此次由用户完成官方授权，并在确认目标账户及隔离凭据目录后由服务器操作人员配置单账户来源；不能将该过程视为已经实现面向所有账户的自助绑定或解绑。**不能把手工添加活动状态当作正式多账户接入流程。**

## 并发与恢复边界

- 同一用户的高驰任务使用同一个 `source_controls` 控制记录。任务取得最长 120 秒租约后，仍须获得凭据目录的文件锁；不同目录也不能绕过同账户租约。
- 每段上游请求之前续期；收到结果后，以 `BEGIN IMMEDIATE` 取得 SQLite 写锁，核实账户存在、来源仍活动、控制代次、租约令牌及到期时间，再在同一事务写入回忆和检查点。失败回滚，旧任务释放租约时只匹配自己的令牌。
- 暂停或恢复改变控制代次并清除租约；回忆导入也在同一写事务改变代次和清除租约，阻止之前已经开始的任务写入。若动作发生在结果提交持锁之后，它会等待提交完成；动作成功返回后旧任务不能再提交。
- **暂停不是撤销高驰授权。** 已发出的请求可能完成，辅助程序可能已经刷新凭据；这里保证的是协调后的新任务和在途任务不能提交，不保证取消已发出的网络请求。
- 进程崩溃后，租约到期才能接管；被接管任务不能提交或清掉新租约。租约依赖单机系统时钟，时间跳变和 SQLite 锁竞争可能导致失败；没有经过多主机与分布式调度设计。
- 离线恢复准备会将已有来源暂停、递增代次并清除租约；旧备份没有控制表时也不会自动创建活动记录。**旧版 worker 和直接调用底层导入函数不受租约约束**，迁移或恢复时必须先停止旧进程，并在启用前验证所有写入入口。

## 尚未完成

仍需通用账户自助授权、重新授权/解绑与凭据撤销、覆盖范围和历史回填、错误状态与告警、限流、手机端验证以及更完整的生产恢复演练。`source_controls` 不保存供应商身份，也不能自行证实辅助程序、账号或凭据归属正确；此次仅在用户确认的单账户授权及专用凭据目录前提下运行。首次同步范围及每日任务的验证记录见[开发记录](开发记录.md)。

来源状态变更、租约续期或检查点变化会使数据导入预览失效；可先暂停后重新预览。暂停后从已存在的服务器快照恢复，也须验证媒体、数据库、身份密钥、旧进程停止及失败回退。
