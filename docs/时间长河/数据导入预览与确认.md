# 数据导入预览与确认

此文描述隔离环境中已实现的 API，不代表生产已更新。它用于产品级 JSON 导入，不是数据库与照片文件的灾难恢复方案。设置页尚无导入界面；客户端 API 仅提供调用基础，接入前必须让用户看到预览并明确确认。

## 操作与现有数据

1. 用已认证账户向 `POST /api/data/import/preview` 提交完整导入 JSON。接口只读，返回 10 分钟有效的 `preview_token`、影响统计和提示。旧版无 `version` 的 JSON 与版本 2 可接受，未知版本或未知顶层字段被拒绝。
2. 显示 `replacements`：分类、账单、健身和回忆分别显示 `replace/preserve`、当前数量和导入数量。**当前实现对明确提供的列表是整体替换，不是合并**；省略字段则保留，显式空数组则清空该类内容。设置只更新列出的受支持字段。
3. 显示跳过的删除标记数 `memories_skipped_by_suppression`、最终抑制标记总数 `suppression_count_after` 和 `sync_checkpoint_reset`。已存在的删除标记会与备份中的标记合并；替换回忆将重置同步检查点。未有删除标记的来源记录可能被后续同步再次收集，预览的 `warnings` 会说明。
4. 用户确认后，将**同一份 JSON**和预览令牌提交 `POST /api/data/import/commit`：`{"data": 导入对象, "preview_token": "预览返回的令牌"}`。令牌对账户、导入内容和预览时数据库快照绑定。
5. 若返回 409，预览已失效、过期、内容变化或被影响的数据变化，必须重新预览；不要悄悄重新确认。若请求超时/响应丢失，提交结果可能未知，应重新读取现状和预览，不能简单断定失败。

旧 `POST /api/data/import` 返回 409 并停止导入；旧客户端无法绕过确认流程。数据库中没有单独的预览行，令牌不包含原始回忆内容；数据库和导入内容的摘要使用带服务端密钥的 HMAC。令牌受 JWT 密钥轮换影响，轮换后须重新预览。预览令牌不应写入日志或长期保存。

## 隔离验证保障

- 预览在独立 SQLite 读事务内获取一致快照；提交在 SQLite `BEGIN IMMEDIATE` 写锁内重新认证、核对摘要并执行导入。提交失败时事务回滚；已测试竞争写锁及模拟部分删除后的失败回滚。
- 令牌绑定账户、数据和现状，过期、篡改、跨账户、数据改变、预览后新增/修改/删除受影响数据均拒绝。重放时只有快照仍完全一致才可能通过；令牌不是严格一次性凭据。
- 确认阶段仍要求正常的账户授权；令牌不能用来登录。返回包含私人数据的导出与预览响应均设置 `Cache-Control: no-store`。
- 缺少账单时不会清空账单。若导入替换分类而没有同时提供账单，且当前已有账单，会拒绝，避免旧账单引用失效。账单分类引用、基本字段类型和列表长度会检查；每类列表最多 10000 条，规范化导入内容最大 10 MiB。

## 仍需完成

- 替换语义与审查中提出的默认合并方案不同；回忆、账单、健身的细粒度合并与冲突解决尚未实现。导入回忆中声明的来源尚无可验证的来源信任标识。不能将一次导入说成不覆盖其他数据。
- 每类记录的语义校验仍不完整；程序通过事务回滚防止部分写入，预览成功不保证所有历史格式一定能提交。导入对象大小限制在请求解析后检查，不能代替反向代理的请求体上限、超时与限流。
- 状态摘要当前需读取该账户相关表中的全部行；大数据量下写锁与内存压力尚未做性能评估。高驰同步、用户数据删除及其他写入发生在提交后仍会继续；任务暂停和代次保护需要来源模块支持。
- 数据库和媒体一致性、媒体内容导出、加密备份、异地备份和完整恢复演练仍未完成；本接口不处理照片原文件。
- 使用新版本服务前需先完成真实数据库迁移、身份及备份恢复检查。旧生产版本、微信平台及手机均未验证。
