归档日期：2026-10-28。本文是恢复工作的入口，描述归档时已知状态；后续接手者先检查 Git、微信后台及服务器的当前状态，历史记录可能已经过时。

## 产品目标与用户偏好

抱布记希望尽可能自动收集生活素材，保存在个人空间里，让用户像在时间长河中自由旅行，偶遇遗忘的普通瞬间。默认仅自己可见，未来可能与伴侣共同记录。首批关注高驰跑步和路线、安卓手机照片；以后再考虑地点、微信读书、网易云音乐、微信支付、ChatGPT 和 DeepSeek 等来源。优先官方授权或允许的导出方式，不能假设所有平台都提供自动同步。

用户希望减少主动记录，允许偶尔补一句话、感悟或段子。安卓照片默认只同步用户选择的相册。用户要求架构按模块演进、阶段性详细测试，并把代码、设计与开发过程提交 Git / GitHub；真实私人数据保存于现有腾讯云服务器。原记账、健身前端入口已移除，不应删除原有服务器数据。用户希望尽量自主连续推进，遇到确实需要其授权或操作时再说明原因。

## 代码与部署

- GitHub 公开仓库：`hxf-root/accounting-miniprogram`；项目中的 `docs/时间长河/开发记录.md` 为按时间追加的历史记录，后面的记录可能更新前面的结论。
- 主要模块：`backend/routers/memories.py` 回忆接口；`backend/coros_worker.py` 和 `backend/integrations/` 高驰同步；`backend/identity/` 和 `backend/routers/wechat_identity.py` 身份与限流；`pages/river/` 时间长河；`pages/settings/` 身份连接；`utils/wechatIdentity.js` 客户端身份适配。
- `deploy/backup_sqlite.py` 使用 SQLite 备份 API 创建一致性快照；`deploy/prepare_restore.py` 只准备离线恢复副本并撤销副本中的短期会话，生成新的 JWT 密钥，不会启用恢复结果。生产恢复还需所有服务切换新 JWT 密钥、保留身份 HMAC 密钥、停止旧服务并验证回退。
- `deploy/check_schema.py` 在内存副本中演练建表，检查字段、非空、主键、唯一约束、索引及原表记录数；不比较所有字段类型、字段值、数据库约束或业务语义，不等于完整恢复演练。`deploy/check_runtime.py` 检查当前进程环境的配置格式，不输出密钥；不能证明实际服务环境、密钥强度、代理链、HTTPS 或外部服务可用。
- **旧 `deploy/deploy.sh` 已故意设置为立即停止**：原脚本没有足够的备份、迁移与回退保障。不要删除这个保护后直接上线；应先设计并测试完整安全部署及失败回退。
- 身份与密码限流均有默认关闭的实验配置。后者按客户端地址限流，不是完整的账户级或分布式防暴力方案；可信代理必须根据真实链路配置，不能信任全网。
- 曾经经用户授权，只在服务器内存中校验备份并按当时代码模拟建表，完整性检查通过、既有表字段存在且记录数保持；没有下载或打印私人记录，也没有改写服务器。该检查没有覆盖所有索引、约束、字段值和恢复过程，检查结果会随时间过期。服务器细节存于本机忽略的私人记录，不要提交或公开。

## 隐私与交接边界

仓库为公开仓库：不要提交真实照片、定位、运动记录、聊天内容、账单、账号密码、令牌、服务器地址、敏感配置、微信后台带会话参数的链接或二维码。`project.private.config.json` 在归档时有用户本地未提交改动，保留原样，不能替用户覆盖、暂存或提交；更换机器后它不会随 Git 自动恢复。

如需用户配合，优先使用官方登录或授权页面，不要求用户在聊天中发送密码、私钥或访问令牌。部署或发布前先核实当前状态、备份、回退及适用的操作授权；不把准备工作、上传、审核和正式发布混为一谈。
